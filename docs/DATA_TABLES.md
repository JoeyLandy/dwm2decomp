# Data tables

Stage M5 of the moddable-decomp goal ([roadmap](ROADMAP.md)), evidence E-0396 in the [evidence log](EVIDENCE_LOG.md).
Generated by `tools/tables_export.py check --doc docs/DATA_TABLES.md`; do not edit by hand. The fields' notes
come from src/records.inc and config/tables.json, where their evidence is.

`python -I tools/tables_export.py export --out local/tables` writes the three tables as JSON from the
reference ROM (into an ignored directory); the check packs them again and runs the game's readers.

## Checks

- SpeciesRecordPointers: 384 monster ids point at 324 distinct records; 0 land outside SpeciesRecords or between records; 0 records are not pointed at.
- SpeciesRecords: packed again from the export, equal to the ROM's 15228 bytes.
- SkillTable: packed again from the export, equal to the ROM's 3876 bytes.
- ItemTable: packed again from the export, equal to the ROM's 1287 bytes.
- LoadSpeciesRecord on tools/sm83.py, for every one of 384 ids: copies exactly the exported record.
- LoadSkillRecord on tools/sm83.py, for every one of 228 ids: copies exactly the exported record.
- LoadItemRecord on tools/sm83.py, for every one of 99 ids: copies exactly the exported record.

## Layouts

### SpeciesRecords

Bank $35, $433B, 324 records of 47 bytes. E-0253 (C1: the 324 records SpeciesRecordPointers points at, 47 bytes each and contiguous up to $7EB7; each is labelled SpeciesRecord_<monster> after the first id that uses it; byte 0 is the family (E-0069) and byte 7 the EXP curve (E-0148); the other bytes are not read here).

| Offset | Bytes | Field |
| --- | --- | --- |
| $00 | 1 | SPECIES_FAMILY: family (StringTable_MonsterFamilies index) (E-0069) |
| $01 | 1 | SPECIES_SEX_RATIO: sex-ratio class: 0 = always male, otherwise (byte & 3) indexes SexChanceByClass (10, 50, 90: the chance of female) in RollChildSexFromSpecies (E-0307, E-0311) |
| $02 | 1 | SPECIES_UNTRIPPABLE: bit 0 becomes bit 4 of the slot's wSlotBodyFlags at battle start (GameMode4_Init_LoadBattleSlots); LegSweep and BigTrip skip or fail on such a target (ChooseTarget_LegSweep, ActionEffect_LegSweep) (E-0310) |
| $03 | 1 | SPECIES_METAL: bit 0 becomes bit 0 of the slot's wSlotBodyFlags: MetalCut multiplies damage by 50 against it (MultiplyDamageBy50IfSlotBodyFlagsBit0, ChooseTarget_MetalCut); a non-zero byte also raises a stat cap from 700 to 999 in battle kind 3 (E-0310) |
| $04 | 1 | SPECIES_JOIN_CLASS: join-chance class 0-7: after a battle BattleEnd_OfferJoin_DecideJoinOffer compares (random mod 200) with the chance table entry for it; 7 = never joins (E-0306) |
| $05 | 1 | SPECIES_UNUSED_05: values 0-3 in the 324 records but never read: every species read goes through wSpeciesRecord, and no code reads its byte 5 (the two whole-buffer users only clear it) (E-0311) |
| $06 | 1 | SPECIES_MAX_LEVEL: base level cap: copied to a new record's $57 (MON_MAX_LEVEL); BattleEnd_Records compares the level with it; ComputeBreedingChild starts the child's cap from it (E-0299) |
| $07 | 1 | SPECIES_EXP_CURVE: the ExpTable row (EXP curve) (E-0148) |
| $08 | 3 | SPECIES_SKILLS: three natural skills: copied to the first three entries of a new record's skill list $3C (MON_SKILL_LIST), the rest $FF (E-0299) |
| $0B | 1 | SPECIES_FIELD_ABILITY: field ability: string index in category $0D, which BeginStringDisplay_Bank08 redirects to bank $95's category 4, StringTable_FieldAbilities: None, Call ship, Call cloud, Smash rock, Burn, Cut, Open door; shown by ShowRecordSpeciesAndSkillNames and the record screens (E-0313) |
| $0C | 6 | SPECIES_GROWTH: six stat growth rows, one per stat in the order of wLevelUpGains (bytes $0C-$11; C1: HP, MP, ATK, DEF, AGL, INT): ComputeLevelUpStatGainsForBattleArg1 passes each to ReadStatGrowthGain, and new and wild monsters pass each to StatFromGrowthRow (E-0299, E-0309) |
| $12 | 27 | SPECIES_RESISTANCES: 27 base resistance levels: copied to a new record's $73-$8D (MON_RESISTANCES); LoadSpeciesResistanceArg4 reads one (E-0299) |
| $2D | 2 | SPECIES_EXP: base EXP word: GameMode4_Init_BuildFoeRecord writes it as the low word of a new battler's 24-bit EXP (battler $18-$19), as MonsterTable bytes 6-7 do for wild monsters (E-0310) |

### SkillTable

Bank $1A, $40D4, 228 records of 17 bytes. E-0032 (C1: the debug mode's skill viewer, GameMode0 state 9, loads 17-byte records with LoadSkillRecord and prints these fields; the screens were read on the emulator; 175 records because the viewer wraps its index at $AF). The meaning of the numbers is not established beyond that the first byte rises across spell families (Blaze 2, Blazemore 4, Blazemost 10). E-0204: LoadSkillRecord takes a 16-bit index (wRecordBuffer) and the 17-byte records continue past the viewer's 175 up to SkillRequirementTable at $4FF8: 228 records; 175-227 have the same layout (no family or type strings in bytes 0-2 for most).

| Offset | Bytes | Field |
| --- | --- | --- |
| $00 | 1 | first number the debug skill viewer shows; rises across a spell family (2, 4, 10 for Blaze, Blazemore, Blazemost) |
| $01 | 1 | skill family: string index in category $12 (1 = Blaze, 2 = Firebal, 3 = Bang, ...) |
| $02 | 1 | skill type: string index in category $13 ('Type A' ... 'Type G') |
| $03 | 1 | low 2 bits: when usable, string index in category $14 (0 None, 1 Battle, 2 Field, 3 Anytime); high nibble: string index in category $10 ('Charge', 'Mixed', 'Cautious', ...) |
| $04 | 1 | target: string index in category $11 after Func_001_5311 ('1 enemy', 'All enemies', ...) |
| $05 | 1 | number shown by the debug skill viewer |
| $06 | 1 | number shown by the debug skill viewer |
| $07 | 1 | number shown by the debug skill viewer |
| $08 | 1 | number shown by the debug skill viewer |
| $09 | 2 | 16-bit number shown by the debug skill viewer |
| $0B | 2 | 16-bit value read by the viewer (wCFF9) |
| $0D | 2 | 16-bit value |
| $0F | 2 | 16-bit value |

### ItemTable

Bank $16, $4CC2, 99 records of 13 bytes. E-0034 (C1: LoadItemRecord copies 13 bytes from here by item id (wD081) to wD084; CheckItemUsable dispatches on the same id; wC61D is a 24-slot bag of such ids, empty at the start of a new game, matching the item menu's 'No items'; the herb handler compares the words at save-record offsets $5B and $5D to refuse use at full HP). 99 records: the next bytes are a different table. The meaning of the fields is not established beyond the first amount being 10, 50, 500, 200 and 2000 for ids 1-5.

| Offset | Bytes | Field |
| --- | --- | --- |
| $00 | 1 | byte 0 (0, 1, 2 or 6) |
| $01 | 2 | 16-bit amount (10, 50, 500, 200, 2000 for the first five items) |
| $03 | 1 | byte 3 (usually $64) |
| $04 | 1 | byte 4 |
| $05 | 1 | byte 5 (never read) |
| $06 | 1 | byte 6 |
| $07 | 1 | byte 7 |
| $08 | 1 | byte 8 |
| $09 | 1 | byte 9 |
| $0A | 1 | byte 10 |
| $0B | 1 | byte 11 |
| $0C | 1 | byte 12 |
